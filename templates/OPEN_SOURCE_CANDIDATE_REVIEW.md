## Functional proof and risk

- **Evidence:** URL + time read + relevant file/section; avoid numbers without source.
- **Input/output parity:** sample fixtures, normal/boundary/invalid/dependency/security tests (plan vs actual clearly separate).
- **License details:** source license, transitive licenses, obligations, counsel needed if unclear; do not assume MIT/Apache.
- **Runtime/supply chain:** install hooks, permissions, egress, secrets, dependency versions, maintainer provenance.
- **Live integration?** NOT_RUN unless Owner authorizes in-scope test.
- **Comparative score:** threshold must-haves first; weighted criteria only after verified; star count is not validation.
